码忆 CodeMem 使用教学

码忆是面向 Java 后端学习者的记忆型学习伴侣：它把你的 Obsidian 笔记当作只读知识库，结合对话上下文和长期记忆回答问题、指出卡点，并把值得记住的内容沉淀到记忆库。

快速开始 页面导航 对话与引用 记忆与指令 知识库与索引 双角色工作流 设置说明 常见问题

快速开始（5 步）

  1. 打开「对话」页，确认右上角显示 后端 UP；如果显示 DOWN，说明服务或数据库没启动。
  2. 进入「API Key」页，按需填写 Embedding 的 Base URL、模型与 Key。只用本地 hash 演示链路时可以不填。
  3. 回到「对话」页，在右侧「知识库」标签的「添加笔记库」里选目录并点 添加并切换，会自动建立索引；已经添加过的库，直接点顶部 重建索引 即可。
  4. 回到「对话」页，输入问题，按 Ctrl + Enter 或点「发送」。回答会流式输出，右侧同时出现引用来源。
  5. 右侧「引用」看本轮用到的笔记片段，「知识库」看当前生效的库、篇数与块数，也可以在卡片里单独重建某个库。
索引完成后，「知识库」标签会显示当前生效库的篇数与块数。数字来自实际扫描结果，笔记增加后重建一次就会同步变化。

对话与引用

每次提问，码忆按固定顺序组装上下文：全局指令 → 本会话工作记忆 → 从笔记中检索到的片段 → 交给模型生成回答。

你会看到什么

  • 流式输出：回答按 token 逐步显示，首字延迟通常在几百毫秒到几秒，取决于模型服务。
  • 引用：右侧「引用」列出本轮使用的笔记片段、来源路径与相关度分数。引用只来自检索结果，不会编造笔记路径。
  • 检索不到时：回答会明确说明知识库没有相关内容，而不是硬编一个来源。

提问建议

  • 问笔记里有的概念时，尽量用笔记里出现过的具体术语，命中率更高。
  • 追问可以省略主语，码忆会带上本会话的工作记忆。

记忆与指令

码忆把「记忆」分成会话内和跨会话两层，另有一份全局指令，避免把整段对话一股脑塞给模型。

类型内容在哪里
工作记忆当前会话最近若干轮对话与摘要对话页自动维护；按会话隔离。
长期记忆对话结束后自动抽取的事实、偏好、卡点与计划，以及手动写入的条目「记忆库」页：按生效中 / 已归档 / 已失效筛选，可归档、恢复或删除。
全局指令自己写的固定要求，每轮回答前注入「指令」页：新增、查看生效中的指令与注入预览。

长期记忆怎么更新

一轮对话结束后，系统会把这一轮放进异步队列，抽取记忆候选；它不会阻塞回答，通常在几秒内出现在「记忆库」里。手动写入的条目立即生效。

右侧标签

  • 引用：本轮用到的笔记片段、路径与相关度分数。
  • 知识库：管理知识源，添加、切换或移除笔记库，分别重建索引或清空知识库。
删掉某条记忆是不可恢复的物理删除；只想让它不再影响回答，用「归档」就够，归档后还能点「恢复」。

知识库与索引

码忆把笔记目录当作 只读 知识源：扫描、切分、建索引，全程不会修改或删除原文件。

「知识库」标签上的按钮

位置按钮作用
顶部工具条重建索引重建下面所有已登记知识源的索引，并汇总每个源扫描、成功、跳过的篇数。
顶部工具条清空索引清空索引并移除已登记的知识源，知识库回到未配置的空状态；笔记文件不受影响，清空后重启也不会自动回填。
顶部工具条刷新来源重新读取知识源列表，不触发扫描。
知识源卡片重建索引只重建这一个知识源的索引，其他源不动。
知识源卡片切换到此库把该库设为生效库并重建它的索引；其他源索引保留，但不参与检索。
知识源卡片移除只是取消登记，不删除磁盘笔记；使用中的库需要先切换后才能移除。

添加笔记库

在「添加笔记库」里填名称（可留空，默认取目录名）、选择类型（Obsidian 笔记库或普通 Markdown / TXT 目录）、填目录绝对路径或点「选择目录…」调系统窗口，最后点「添加并切换」。添加后会自动成为生效库并建立索引。

同一时间只有一个生效库

可以登记多个笔记库，但检索只使用当前生效的那一个。切换生效库时会重建它的索引；其他库的索引保留着，切回去不需要重新扫描。

索引过程

  • 按 Markdown 标题层级切块，保留标题路径、双链和 frontmatter 元数据。
  • 用内容哈希做增量：没变的笔记直接跳过，只有改动或新增的才重新向量化。
  • 检索时同时走两条路：向量相似度 + 中文关键词匹配，再用融合排序取前几条。
更换 embedding 服务地址、模型或维度后，向量签名会变化，必须重建索引，否则旧向量和新模型不匹配，检索会不准。

双角色工作流

不是所有问题都值得两个角色。码忆先用规则路由判断，再决定是否启用审查。

  • 什么时候触发：学习计划、卡点诊断、代码评审、跨会话追问，或你明确要求严格审查；概念解释、事实问答走单角色，延迟低。
  • 怎么分工：Mentor 先起草；Reviewer 只基于证据（引用片段、笔记、记忆）指出缺证据、与证据冲突或代码错误，不重写答案，也不引入新事实。
  • 怎么修订：挑出问题时 Mentor 最多修订一次；仍不通过会标注未解决问题并附证据，不会无限循环。
  • 在哪看：双角色在后台完成，界面上不单独展示时间线；触发时回答会稍慢一些。
双角色会多 1–2 次模型调用，因此更慢；日常概念问题不会触发。

API Key 与知识库设置

知识库（对话页右侧「知识库」标签）

  • 当前使用：显示生效的库、路径和索引规模；只读扫描，不改原笔记。
  • 添加笔记库：填名称（可留空）、选择类型、填目录绝对路径，点「添加并切换」。
  • 重建索引（顶部）：重建下面所有已登记知识源，完成后汇总每个源的结果。
  • 重建索引（卡片）：只重建该知识源。
  • 清空索引：删除全部索引并移除知识源登记，知识库回到未配置状态；笔记文件不动。

API Key 页

  • Key 只保存在服务进程内存里，不写文件、不写数据库、不回显、不写日志。
  • 因此服务重启后需要重新输入；想长期生效，就在启动前设置环境变量 CODEMEM_EMBEDDING_API_KEY（或 OPENAI_API_KEY）。
  • 更换服务商要同时改 Base URL 和模型名，保存后重建索引。
  • 「保存并重建索引」适合第一次配置或换模型：一步完成保存并重建全部知识源。
重建后如果提示「扫描 N 篇，失败 N 篇」，最常见原因是 Key 未配置或 Base URL 不通。按提示到 API Key 页检查后重试即可。

常见问题

重建索引显示扫描 27 篇、成功 0 篇、跳过 27 篇？

说明笔记内容没有变化，全部命中哈希、无需重新向量化，属于正常结果；篇数和块数仍以前一次索引为准。想强制重算，可以先清空索引再重建。

知识库是空的、0 篇 / 0 块？

要么还没添加笔记库，要么点过「清空索引」（会连同知识源一起移除）。在「添加笔记库」里填目录重新添加即可；清空后重启不会自动回填。

重建索引提示失败？

先看提示里的失败原因。若是「embedding API key is not configured」，说明 Key 没填或服务重启后丢失；填好 Key 再点重建，不需要重启服务。若扫描数也是 0，检查知识源路径是否存在、目录里是否有 .md 或 .txt 文件。

服务重启后 Key 又没了？

这是设计行为：Key 只存内存。把 Key 放进环境变量再启动，或用「保存并重建索引」重新配置一次。

中文提问返回的结果不相关？

确认索引用的是真实 embedding 而不是本地 hash。hash 只适合无 Key 时演示链路，语义召回很弱；换回真实服务后重建索引即可。

记忆没有立刻出现在记忆库？

抽取是异步的，通常在几秒内完成，刷新「记忆库」页即可看到；手动写入的条目会立即生效。

删除会话会删掉什么？

会级联清理该会话的消息、轮次、抽取记录、Agent 轨迹、异步事件和工作记忆；不会删除笔记，也不会删除长期记忆与全局指令。

服务地址是什么？

默认 http://127.0.0.1:8080，主界面在 /web/。健康检查用 /actuator/health。

数据与安全

  • 笔记目录只读，索引不会写回 Obsidian。
  • 「清空索引」只删除索引与知识源登记，不删除磁盘上的笔记。
  • API Key 只在运行时内存中，不落盘、不回显。
  • 笔记内容在提示词中只作为资料，不执行其中的指令。
想了解实现细节，可查看源码里的 knowledge、chat、memory 这几个包。
